# Networka release qualification

24 November 2026

This report records qualification for Networka 0.2.0 with Scrapli 2. Build names and Python versions describe the releases tested in November 2026. The current development branch requires Python 3.15 or later.

## Packaging and infrastructure

| Problem | Fix | Proof |
| --- | --- | --- |
| A fresh 0.1.13 install could resolve the rewritten Scrapli package and a libtmux version that removed APIs used by the CLI. | Built 0.1.14 from the published tag and constrained the dependencies at the package boundary. Kept the maintained branch on the current tmux API and moved Scrapli 2 to a separate candidate. | Clean wheel and source installs for all three versions started `nw` and passed dependency checks on macOS arm64 and Linux arm64 and x86-64. The candidate loaded its native library on both Linux architectures. |
| Release routing treated the `a` in `refs/tags/` as a prerelease marker. Local and CI environments could also select different Python interpreters. | Parse the version once using PEP 440. Install each build artifact independently before publication. Use uv 0.13.9 and explicitly select each CI interpreter. Use the same preflight when preparing a maintenance release. | Canonical stable and prerelease routing checks and the 0.1.14 preflight and dry run passed. The maintained and candidate suites passed on Python 3.11–3.15. The dry run uses the checked preflight marker for the exact release commit. |

## File transfer and pooled sessions

| Problem | Fix | Proof |
| --- | --- | --- |
| Upload verification put the remote path in the name of a local temporary file, so upload into a directory succeeded but returned failure after repeated verification attempts. | Use a generated local name and pass the original remote path directly to the existing download and SHA-256 checks. | An identical nested-path upload returned failure before the fix. All three rebuilt wheels verified the checksum and returned the original 256 bytes from the disposable Linux server. |
| SFTP ignored strict SSH host-key checking, and the legacy Paramiko CLI adapter did not request the known-hosts file. | Load the known key before SFTP authentication and verify the negotiated key for the configured host and port. Enable the legacy adapter’s known-hosts lookup in strict mode. | Each rebuilt wheel authenticated with the trusted key. SFTP rejected both a missing and mismatched key. The legacy CLI connected via Paramiko and the candidate via native SSH2 in strict mode. |
| Requested removal after SFTP download used a RouterOS command and could still report success when removal failed. | Remove the same remote path through the already-authenticated SFTP session and propagate removal errors. | All three wheels downloaded the same bytes, removed the requested remote file, and confirmed its absence through a second SFTP download. |
| The pool could replay a command when the device had already executed it. Transfer context managers could also attempt to yield a second session after an operation failed. | Limit retries to connection setup. Run the command or yield the connected session after the retry block. | An actual pooled command that wrote one byte and closed its shell produced two bytes before the fix and one after it. The fixed call returned the unconfirmed result. Eleven existing upload CLI cases now exercise the current command and strict success or failure expectations. |

## Scrapli 2 compatibility and release status

| Problem | Fix | Proof |
| --- | --- | --- |
| Scrapli 2 rewrote command execution, transport configuration, and prompted input. RouterOS needs console settings that the native wheel omitted. | Map the existing transport interface to Scrapli 2.0.4, use verified RouterOS console options, and keep Paramiko for SFTP. Report interrupted confirmations as unconfirmed. | In a disposable RouterOS 7.20.6 emulator, all three builds returned the expected identity and version over a reused SSH session. A native session answered a literal prompt against a local shell. |
| Initial qualification deferred Cisco enable-password escalation, WSL2, and device restart checks. Upstream supplies no wheel for Intel macOS or native Windows. | Release 0.1.14 on the verified legacy driver. Keep the refreshed 0.2 and native 0.3 builds available for further qualification. | 0.1.14 passed 891 tests with 39 skipped on Python 3.13. Both development lines passed 1,134 tests with 31 skipped per Python version from 3.11 through 3.15. Production publication and hosted CI remain pending. |

## Upgrade and rollback qualification

| Problem | Fix | Proof |
| --- | --- | --- |
| A default published 0.1.13 installation could fail before the CLI started. A fresh 0.1.14 install alone did not prove that existing operators could upgrade. | Keep the compatibility constraints in the release metadata so the resolver repairs the existing environment. Keep the existing inventory format. | On Linux arm64, upgraded a working 0.1.13 environment to the 0.1.14 wheel, repaired a broken 0.1.13 environment with the 0.1.14 source archive, and rolled back to 0.1.13 with its known compatible dependency versions. The same Cisco IOL sequence returned matching privilege and interface output on each path. All four configuration files had identical SHA-256 checksums. An isolated `uv tool upgrade networka` also repaired the launcher when supplied the local release artifacts. |
| The initial native candidate broke normal upgrades by leaving `scrapli2` and the legacy `scrapli` distribution installed together. The dependency checker could still pass. | Use the native implementation under the existing distribution name, `scrapli==2026.11.12`. It contains Scrapli 2.0.4 and replaces the legacy files during resolution. | Reproduced the mixed import failure, then upgraded from 0.2 to the corrected 0.3 candidate and downgraded to 0.1.14 in the same environment. Each transition left exactly one owner of the `scrapli` import. Native and legacy drivers both ran commands on IOL after the corresponding transition. Use a fresh environment for an earlier unpublished preview that installed the separate `scrapli2` distribution. |
| The first qualification covered an older RouterOS version and had no Cisco execution results. | Run isolated lab sessions against the exact RouterOS release and the existing Cisco IOL image. | On RouterOS 7.25.2, 0.1.14 and 0.2 returned the expected identity and version across a reused session. Both verified a 256-byte SFTP upload, downloaded identical bytes, and confirmed remote removal. On Cisco IOL 17.18.02, both inventory types returned version, management interface, and privilege level. The corrected native build reported a rejected IOS-XE command and kept the session usable. |
| Scrapli 2 could return blank or misaligned command output on RouterOS 7.25.2. | Keep 0.1.14 on the verified legacy transport. Use RouterOS plain-console login with a single carriage return in the native adapter. The legacy driver keeps its existing console settings. | The original settings misaligned replies on 7.25.2. Plain-console login plus a single carriage return kept 288 alternating replies aligned on the rebuilt wheel across 7.20.6 and 7.25.2 with OpenSSH and native SSH2. Twelve independent sessions also ran long commands. The candidate verified an SFTP upload, downloaded matching bytes, and confirmed removal on 7.25.2. |
| The bundled spanning-tree sequence monitored only a bridge named `bridge`. RouterOS moved MLAG settings and status to the bridge in 7.22. | Select bridge IDs with `/interface/bridge/monitor [find] once`. Keep the existing detailed bridge output so newer RouterOS releases expose their `mlag-*` fields. | The old selector missed the test bridges. The packaged sequence returned both test bridges on 7.20.6 and 7.25.2 on all three builds. On 7.25.2, `print detail` exposed the configured `mlag-peer-port`, and monitor reported `mlag-state: peer port not running` on the disconnected test bond. The 7.20.6 CHR image exercised bridge monitoring; hardware MLAG remains untested. |
| Disposable qualification resources could outlive the release check. | Destroy the IOL topology and remove only the labeled RouterOS containers and named test environments. | Verified no matching release containers or IOL management network remained. |

The device checks cover the package upgrade and rollback, SSH command execution, and the listed file transfers. Router firmware upgrades and downgrades, active MLAG peer failover, and WSL2 remain untested. MikroTik documents MLAG configuration loss when downgrading across the RouterOS 7.22 change. [MikroTik release notes](https://forum.mikrotik.com/t/v7-22beta-development-is-released/267611/2)

## Restart and enable qualification

| Problem | Fix | Proof |
| --- | --- | --- |
| A confirmed RouterOS reboot disconnected SSH before Scrapli could see another command prompt. Earlier code also treated a generic timeout as proof of a reboot. | Send the reply once at the exact confirmation prompt. Report the observed disconnect only after sending the reply, handle the native SSH2 socket-loss result, and close a dead session without issuing a logout command. | The rebuilt RC on RouterOS 7.25.2 kept the session and uptime after answering `n`. After answering `y`, OpenSSH and native SSH2 both reconnected to the same device with lower uptime. A missing prompt remained an unconfirmed operation. |
| Networka did not supply a separate Cisco enable secret to Scrapli. | Load the device or default enable secret through the existing credential environment convention. Supply it only to the CLI driver and suppress upstream debug messages for those connections. | On IOL 17.18.02, a fresh login started at privilege 1. Both `cisco_ios` and `cisco_iosxe` reached privilege 15 with the proper secret, honored the per-device override, and refused wrong and missing secrets. Debug logs contained neither test secret. |
| IOL initially refused SSH reload because its boot register selected ROM monitor. | Set the normal IOS boot register on the disposable node and use the same tracked confirmation for the Cisco reload path. | Networka submitted the reply to the Cisco reload prompt. The same node returned at zero minutes uptime and the privilege-1 login elevated to privilege 15 again. |

The existing suite passed on Python 3.11–3.15 with 1,134 tests passed and 31 skipped per version in isolated source checkouts.

The artifacts are in `dist/rebirth` in the local checkout.
